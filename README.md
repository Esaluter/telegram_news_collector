# Telegram News Collector

Самостоятельный сборщик сообщений одной Telegram-группы для Python 3.11 и
Bothost Basic. Он использует правила рабочего проекта `monitoring_bot_v2`:

- `python-telegram-bot` и long polling;
- только заданный `GROUP_ID`;
- текстовые сообщения и подписи к медиа, кроме команд;
- дедупликация по `chat_id:message_id`;
- самостоятельные хештеги `#ижс` и `#корп` без учёта регистра;
- локальный атомарный JSON-архив.

ИИ, кадастр, мониторинговый пайплайн, отчёты и email отсутствуют.

## Состав

- `collector.py` — точка входа Bothost;
- `storage.py` — локальный архив, дедупликация и очередь повторной доставки;
- `news_record.py` — существующие правила хештегов/ссылок и безопасная схема строки;
- `apps_script_client.py` — отправка пакетных идемпотентных запросов;
- `import_history.py` — проверка и пакетный импорт старого JSON;
- `apps_script/Code.gs` — приёмник Google Apps Script;
- `tests/` — офлайн-тесты Python и Apps Script.

Исходный `monitoring_bot_v2` и его файлы данных этому проекту не нужны при
обычной работе и не входят в пакет развёртывания.

## 1. Подготовка Google-таблицы

В существующей закрытой таблице создайте два листа с точными именами:

1. `Все новости`
2. `ИЖС-КОРП`

В строку 1 каждого листа, начиная с A1, вставьте заголовки в этом порядке:

```text record_key	Дата сообщения	Группа	Отправитель	Источник пересылки	Текст новости Ссылки	Хештеги	ID сообщения	ID группы	Дата сбора
```

Пользовательские колонки (`Проверено`, `Комментарий`, `Ответственный` и т.п.)
добавляйте только справа, начиная с колонки L. Скрипт пишет только A:K, только
при добавлении новой строки. Существующие строки он не обновляет. Колонку A
рекомендуется скрыть и защитить от ручного редактирования.

Полный Telegram-объект в Google не отправляется. В таблицу попадают только
поля A:K; ID/username отправителя, ответы, фото-ID и другие технические поля
остаются в локальном JSON.

## 2. Настройка Apps Script

1. Откройте таблицу → **Расширения → Apps Script**.
2. Замените содержимое `Code.gs` файлом [apps_script/Code.gs](apps_script/Code.gs).
3. Откройте **Настройки проекта → Свойства скрипта** и добавьте:
   - `SPREADSHEET_ID` — часть URL таблицы между `/d/` и `/edit`;
   - `COLLECTOR_SECRET` — случайная длинная строка, отдельная от Telegram token.
4. Выберите **Развернуть → Новое развертывание → Веб-приложение**.
5. Выполнять от имени владельца таблицы. Доступ выберите такой, чтобы Bothost
   мог выполнить POST без интерактивного входа. Защиту запроса обеспечивает
   `COLLECTOR_SECRET`; URL и секрет нельзя публиковать.
6. Скопируйте URL развертывания, заканчивающийся на `/exec`.

При изменении `Code.gs` создавайте новую версию развёртывания. Сам проект это
развёртывание автоматически не публикует.

Apps Script проверяет секрет и схему, ограничивает пакет 100 строками и
дедуплицирует каждый лист отдельно. Поэтому повтор запроса безопасен. Если
один лист был записан, а второй временно недоступен, следующий запрос добавит
только отсутствующую строку. Действие `repair`, выполняемое сборщиком при
старте, восстанавливает недостающие строки между двумя листами по данным уже
записанного листа.

## 3. Локальная проверка

Требуется Python 3.11.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Если установлен Node.js, отдельно проверьте фактический `Code.gs`:

```powershell
node tests/apps_script_harness.js
```

Эти тесты не обращаются к Telegram или Google.

## 4. Проверка и импорт истории

Сначала выполните только локальную проверку архива. Она читает исходник, но не
изменяет его и не обращается к сети:

```powershell
python import_history.py --archive "C:\Users\Admin\Desktop\monitoring_bot_v2\data\group_news.json"
```

Команда покажет актуальное число уникальных строк и строк для листа
`ИЖС-КОРП`. Пока старый сборщик работает, архив продолжает расти, поэтому
ориентируйтесь на вывод dry-run непосредственно перед импортом. До реального
импорта выборочно проверьте допустимость переноса внутреннего текста в закрытую
Google-таблицу.

После развёртывания Apps Script и заполнения `.env` запустите импорт явно:

```powershell
python import_history.py --archive "C:\Users\Admin\Desktop\monitoring_bot_v2\data\group_news.json" --send
```

Импорт идёт пакетами по 50 записей. Его можно повторить целиком: Apps Script
не добавит существующие `record_key` и восстановит запись, которой не хватает
на одном из листов. Исходные JSON/XLSX не изменяются.

## 5. Настройка Bothost

1. Создайте Python-приложение с Python 3.11.
2. Загрузите файлы проекта без `.env`, `tests`, локального JSON и исходного
   архива мониторинга.
3. Установите зависимости из `requirements.txt`.
4. Добавьте переменные из `.env.example` в защищённых настройках Bothost.
5. Команда запуска:

   ```text
   python collector.py
   ```

6. Оставьте один экземпляр процесса. Два long-polling процесса с одним
   Telegram token будут конфликтовать.

Обязательные переменные:

- `TELEGRAM_BOT_TOKEN`;
- `GROUP_ID`;
- `GOOGLE_APPS_SCRIPT_URL`;
- `GOOGLE_APPS_SCRIPT_SECRET`.

Локальный `data/group_news.json` хранит полный объект Telegram и статусы
доставки. При ошибке Google запись остаётся `pending` и повторяется каждые
`SYNC_RETRY_SECONDS`. Серверная дедупликация Google остаётся источником
идемпотентности, даже если локальный файл был восстановлен из старой копии или
потерян при redeploy.

Есть фундаментальное ограничение: если Google полностью недоступен, Telegram
уже подтвердил update, а диск Bothost одновременно безвозвратно потерян, получить
текст сообщения повторно через Bot API невозможно. Для этого сценария нужен
гарантированно постоянный диск/backup либо отдельная внешняя очередь. Для
обычных перезапусков, повторных запросов и частичного сбоя листов текущей схемы
достаточно.

## 6. Первый запуск

1. Остановите старый `telegram_bot_v2.py`.
2. Убедитесь, что старого процесса с тем же token больше нет.
3. Разверните и настройте Apps Script.
4. Создайте оба листа и проверьте заголовки A:K.
5. Заполните секреты Bothost.
6. При необходимости импортируйте историю командой `--send` только один раз;
   повторный импорт безопасен.
7. Запустите `python collector.py` на Bothost.
8. Отправьте одно тестовое сообщение без тегов и одно с самостоятельным
   `#ижс` или `#корп`.
9. Проверьте: первое есть только в `Все новости`, второе — в обоих листах,
   а повторный запуск не добавляет дублей.
